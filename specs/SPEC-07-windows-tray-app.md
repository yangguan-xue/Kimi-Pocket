## 1. 目标与范围

为 Windows 用户提供常驻任务栏通知区域的 Kimi Code 额度监控应用。鼠标停在托盘图标上，即可查看当前套餐、5 小时额度、周额度和套餐总额度；移开后自动收起，不打断正在进行的工作。

本版以 macOS 的轻量悬浮体验与信息种类为参考，重新设计 Windows 面板。视觉关键词为：**不透明、黑灰白、克制、清晰、紧凑**。高级感来自数字层级、对齐和留白。

### 1.1 实施基线

| 项目 | 默认方案 |
| --- | --- |
| 产品形态 | 原生 Windows 托盘应用，正常运行时不显示主窗口和任务栏按钮 |
| 支持平台 | 首期验收 Windows 11 x64；Windows 10、ARM64 不纳入首期交付承诺 |
| 日常交互 | 悬浮展开，移出收起；左键切换可见性；不提供钉住按钮 |
| 信息优先级 | 5 小时额度优先，其次周额度、套餐总额度 |
| 数据表达 | 三项统一展示“剩余”，条形填充量统一表示剩余比例 |
| 视觉 | 默认深色，完全不透明；不使用毛玻璃、蓝色和装饰性光晕 |
| 技术候选 | 推荐 .NET 10 LTS + WPF + Win32 通知区域接口 |
| 交付方式 | 首期免安装 ZIP，包含自带运行时的应用；不开启自动更新 |

2026-11-04 用户确认示意图并要求以图为标准开发；上述方案作为任务拆分与实施基线。确认设计不代表对应能力已实现，变更主视觉或技术路线应先同步规范。

### 1.2 首期功能

- 托盘常驻、悬浮额度面板、手动刷新、自动刷新。
- Token 配置、校验、替换与删除，Windows 凭据管理器存储。
- 离线、凭证过期、额度不足、加载与数据缺失状态。
- 单实例、Explorer 重启恢复、多显示器与 DPI 适配。
- 极简设置窗口，包含凭证与可选的开机启动设置。

### 1.3 暂不纳入

完整主窗口、历史统计、多账号切换、桌面小组件、可拖动仪表盘、常驻钉住、主题编辑器、自动更新、商店发布。首期也不做通知轰炸、呼吸动画和大面积图表。

## 3. 视觉规范

### 3.1 表面、尺寸和颜色

尺寸单位为 DIP；截图与实机验收应标注系统缩放比例。

| 属性 | 目标值 / 规则 |
| --- | --- |
| 面板宽度 | 360 DIP；可用工作区不足时缩窄至可用宽度，不超出屏幕 |
| 正常内容高度 | 正常状态目标 376 DIP，与已确认示意图一致；异常或文字放大时按内容增高，不得裁字 |
| 内边距 | 20 DIP |
| 外圆角 | 14 DIP |
| 面板填充 | `#141414`，静止状态 Alpha = 1 |
| 边框 | `#303030`，1 DIP，避免双层描边 |
| 主文字 / 数字 | `#F2F2F2` |
| 次要文字 | `#A6A6A6` |
| 辅助文字 | `#929292`，仍需满足正文对比度要求 |
| 进度条底轨 | `#333333` |
| 进度填充 | `#DEDEDE`，三项一致 |
| 按钮悬浮背景 | `#262626` |
| 键盘焦点 | `#BDBDBD` 实线轮廓，清晰可见 |
| 阴影 | 最多一层中性黑色低强度外阴影；不使用发光、彩色阴影和内发光 |

不使用渐变、蓝色/青色点缀、绿色在线灯、彩色告警条。系统托管的界面不计入自绘配色限制；高对比度模式下优先采用系统可读颜色。

内容表面和窗口主体始终不透明；圆角外部的裁切区域、阴影不属于背景材质。不可使用整个窗口 `Opacity` 淡入，避免动画期间透出桌面。

### 3.2 排版与控件

- 界面字体优先 `Segoe UI Variable` / `Segoe UI`，中文回退系统中文字体。
- 主百分比数字采用约 52 DIP、等宽数字，以已确认示意图的字重和比例为准；百分号缩小并与数值底部对齐；数字字体优先 `Cascadia Mono`，回退 `Consolas`。
- 标题 14 DIP / 半粗体；分区标签 12 DIP；辅助文本和状态 11–12 DIP；普通数值 14 DIP。
- 百分号与数值作为同一可访问文本；小数不显示，使用常规四舍五入。
- 顶部品牌和套餐左对齐，数值与右侧操作按统一垂线对齐。
- 刷新、设置按钮可视图标约 14 DIP，点击区域至少 28 × 28 DIP，带可访问名称。
- 不显示原始 API 计数、JWT 字段、技术错误栈；错误文案给出用户可执行动作。

### 3.4 分段和百分比契约

统一定义 `remainingRatio = clamp(remaining / limit, 0, 1)`，仅在字段有效且 `limit > 0` 时计算。所有数字和条形表达剩余比例；可访问名称也必须包含“剩余”。

对 N 段中的第 i 段（i 从 0 起）：`fill(i) = clamp(N × remainingRatio - i, 0, 1)`。允许最后一个非空段部分填充，禁止向上取整点亮整段。段间隙为 4 DIP，条高 5 DIP；设备像素舍入后段宽差不得超过 1 个物理像素。

百分比显示为 `round(100 × remainingRatio)`，图形使用未取整比例。若实际剩余大于 0 且四舍五入结果为 0，显示 `<1%`；若实际尚未全满且结果为 100，显示 `>99%`。0% 和 100% 仅用于精确端点。

例如 `remainingRatio = 0.58`：7 段为 4 个满段、第 5 段填充 6%、最后 2 段为空。缺失、无法解析、非正数上限的数据展示 `—` 与不可用轨道，不用 100、60 等默认值模拟真实余额。

## 4. 托盘与悬浮状态机

### 4.1 基本交互

| 事件 | 行为 |
| --- | --- |
| 指针首次进入图标有效区域 | 启动 180 ms 停留计时；期间离开则取消 |
| 停留达到 180 ms | 展开已有缓存面板，满足条件时后台刷新 |
| 指针从图标移向面板 | 允许 300 ms 跨越空隙，不立即隐藏 |
| 指针进入面板 | 取消隐藏计时，面板内的刷新、设置可以点击 |
| 同时离开图标和面板 | 300 ms 后隐藏；期间重新进入任一区域则取消 |
| 托盘左键 | 隐藏时立即显示；显示时立即隐藏；显示后仍遵循离开收起规则 |
| 面板外鼠标点击 | 立即关闭；不吞掉该次点击 |
| 托盘右键 | 关闭额度面板并打开菜单：刷新、设置、退出 |
| 打开设置 | 关闭悬浮面板，打开可激活的设置窗口 |
| 锁屏、休眠、退出 | 关闭面板，取消悬浮计时与相关探测 |

左键主动隐藏后，直到指针离开图标才能再次武装悬浮，避免点击关闭后 180 ms 又弹出。菜单与设置接管期间不响应悬浮展开；关闭后同样需退出图标再进入。

状态至少区分 `Hidden`、`PendingOpen`、`Visible`、`PendingClose`、`Suppressed`。定时器使用可取消机制及代次标识，过期回调不能打开已关闭的窗口。右键菜单、设置窗口和锁屏分别持有抑制原因；仅释放自己持有的原因，任一原因仍存在时点击与键盘入口均不得重开面板。菜单关闭时若设置或锁屏仍持有抑制，不将焦点归还托盘。

### 4.2 Windows 事件与实现约束

- 使用 `Shell_NotifyIconW` 注册图标，添加后设置 `NOTIFYICON_VERSION_4`；Explorer 重启后重新添加并重新设置版本。[R1]
- `NIN_POPUPOPEN` / `NIN_POPUPCLOSE` 用于富提示生命周期；不假定系统的悬浮消息在指针进入时立即到达。应用 180 ms 计时从首个有效图标移动事件与命中确认开始；系统消息与点击统一进入同一状态机，避免重复开关。[R1][R3]
- 仅在候选悬浮或面板可见期间，可使用约 40–50 ms 的有限指针/按键状态探测补足离开及外部点击。隐藏待机时停止探测；不得使用常驻全局鼠标/键盘 Hook 或每帧轮询。
- 关闭系统普通 Tooltip，避免它与自绘面板叠加；保留图标名称及可访问入口。`NOTIFYICON_VERSION_4` 下不设置 `NIF_SHOWTIP`。[R3]
- 展开无需等待网络；浮窗隐藏后停止界面秒级计时与动画。

### 4.3 焦点与键盘

悬浮展开不得激活窗口、移动插入光标或中断用户在其他应用中输入；采用不激活显示路径，实际以前台窗口和输入落点验证。[R6]

键盘从系统通知区域选择图标并按 Enter / Space 时，支持进入可操作面板。此时允许按用户明确操作激活面板，Tab 可遍历刷新、设置，Esc 或失去前台焦点关闭，并将焦点合理返回通知区域。键盘打开时不因当前鼠标位于面板外立即收起；鼠标进入面板后可回到正常悬浮规则。

纯鼠标悬浮且面板未获得焦点时，不全局拦截 Esc。设置窗口始终支持 Esc 关闭；关闭设置不退出托盘进程。

### 4.4 动效

首次出现可在 100–120 ms 内完成最多 4 DIP 的短距离位移，表面全程不透明；关闭不超过 100 ms。遵从系统减少动画设置，关闭动画后直接显隐。无缩放弹跳、呼吸、自动滚动和循环装饰动画。

## 5. 定位、任务栏和显示器

- 使用 `Shell_NotifyIconGetRect` 获取实际图标矩形；基于该矩形所在显示器计算位置。[R2]
- 常规底部任务栏中，面板显示在任务栏上方，优先右对齐图标，间隔约 8 DIP；始终钳制在当前显示器工作区内并保留约 8 DIP 边距。
- 不硬编码主屏右下角、任务栏高度或屏幕正坐标；处理副屏在左侧/上方的负坐标。
- 采用 Per-Monitor DPI 感知，物理屏幕坐标与 WPF DIP 经明确转换后再使用；跨屏、缩放变化、显示器热插拔后重算。[R7]
- 图标在系统溢出区时，以可见的实际图标为锚点；面板不得抢焦点而导致溢出区自行关闭。若溢出区关闭并使图标消失，取消候选展开或关闭面板。
- 不强制修改用户的托盘显示偏好。首次设置可提示“可将图标拖到任务栏通知区域，方便随时查看”。
- 图标矩形不可获得时，取消悬浮展开；明确点击/键盘操作可按有效事件锚点回退定位，禁止突然出现在另一块屏幕。
- 自动隐藏任务栏时，不修改任务栏设置、不调用强制前台抢占。需要实机验证从图标到面板的跨区行为；任务栏收起但指针仍在面板上时保持面板，指针离开后按规则关闭。

## 6. 托盘图标

采用识别度清晰的单色 Kimi Pocket 图形，分别准备深色和浅色任务栏版本；支持 16、20、24、32、48 px 图标资源与对应 DPI 选择。不能依赖 Windows 自动为任意图标反色。[R3]

- 正常：简洁单色图标。
- 5 小时剩余 ≤20% 且 >5%：增加静态小点，同时面板显示“额度偏低”。
- 剩余 >0 且 ≤5%：静态叹号标识，面板显示“即将用尽”。
- 精确为 0：显示“当前额度已用尽”；其余两项低额度在各自区域标识。
- 未配置 / 认证失效 / 无可用数据：使用不同于额度提醒的空心或断开标识，面板显示具体状态。

图标不闪烁、不显示彩色呼吸灯；断网且仍有缓存时优先展示“数据未更新”的状态，避免把旧余额当作实时告警。状态优先级：凭证不可用 > 无有效数据 > 数据过期 > 低额度 > 正常。

## 7. 数据、刷新和真实性

### 7.1 接口与归一化

沿用 SPEC-02 中两个 POST 接口、请求体与认证请求头；基地址与当前客户端一致，为 `https://www.kimi.com/apiv2`。这是项目当前使用的接口契约，不假定外部接口长期稳定。

- 使用原生 `HttpClient` 请求，不增加中转服务。
- 对 `FEATURE_CODING` 精确匹配；5 小时窗口仅匹配 300 分钟或 5 小时，不把任意分钟窗口当作 5 小时。
- 区分缺失、格式非法、真实 0 和有效数字；负值、剩余大于上限、单位不符需标为不可用并记录脱敏诊断，不能静默画满。
- 保留服务端的套餐标题、到期时间、resetTime；不默认用户是 Kimi Pro，不从本地推算套餐额度。
- 单一接口失败时允许显示另一接口成功提供的独立分区；不得据此伪造完整成功快照。各分区携带自己的更新时间与错误状态。
- 用量快照与倒计时分开：倒计时归零只显示“等待额度更新”并触发去重刷新，不能本地把额度恢复成满值。
- 总额度、周额度、5 小时额度不可互相替代。会员天数按有效到期时间计算，过去时间显示“会员已到期”。

### 7.2 刷新调度

- 有有效 Token 时启动刷新，成功后默认 60 秒；5 小时已用比例 >70% 时缩短至 30 秒。
- 悬浮展开时先画缓存；缓存超过 15 秒或没有快照时，触发一次静默刷新。
- 自动刷新、展开刷新、手动刷新共享同一在途请求；手动按钮点击后短暂禁用，避免重复请求。
- 一轮刷新整体超时 15 秒；失败按 60 / 120 / 300 秒退避，成功后恢复正常周期；限流尊重有效 `Retry-After`，等待期间禁止手动刷新绕过限流。
- 401、明确的认证失败或 JWT 过期时停止自动请求，提示更新 Token；403 单独区分权限/订阅问题，不循环重试或自动认定 Token 过期。
- 网络断开、休眠时暂停定时请求；网络恢复或唤醒后合并为一次刷新，不积压补发。
- Token 替换/删除时取消旧请求并递增凭证代次；旧请求晚到的结果不能覆盖新账号或重新填充已清除的数据。
- 界面显示“刚刚更新 / N 分钟前更新”；任一分区超过 2 分钟未成功同步时明确标记旧数据，不因其他分区成功而清除标记。
- 缓存首期仅保存在内存中，重启后重新获取；不在磁盘保存账户用量与原始接口响应。

## 8. 首次使用、设置与异常界面

### 8.1 首次启动

创建托盘图标后，无有效凭证时打开一次设置窗口，引导粘贴 Token。用户关闭设置后保留托盘。未配置时悬浮显示“添加 Token，开始查看额度”和“打开设置”，不展示虚构百分比或套餐。

### 8.2 设置窗口

约 420 DIP 宽，可正常获得焦点，沿用不透明灰阶视觉。只包含：

1. Token 密码输入框，默认隐藏，按需临时显示；保存前做格式、字段和到期时间预检。
2. “保存并验证”操作及清晰的执行结果。替换已有凭证时先验证候选，成功后再提交；验证失败保留原凭证，不把网络故障误报为格式错误。
3. 删除已保存凭证的明确操作，执行后清空快照、停止刷新并取消旧请求。
4. “登录 Windows 时启动”开关，默认关闭；仅用户开启后写入当前用户启动配置，无管理员权限要求。
5. 应用版本、关闭入口。关闭窗口后继续常驻。

不自动读取浏览器 Cookie、剪贴板或其他端的凭证。首次验证失败允许编辑重试，不自动保存无法确认有效的候选凭证。

### 8.3 状态内容

| 状态 | 文案 / 行为 |
| --- | --- |
| 首次加载，无缓存 | 保留稳定的版式占位，数字为 `—`，显示“正在获取额度” |
| 后台更新，有缓存 | 保留当前数据，底部显示“正在更新”，禁止跳白与整体闪烁 |
| 无网络，有缓存 | “网络不可用 · 显示上次数据”，保留各分区真实时间 |
| 无网络，无缓存 | “网络不可用”，提供重试；不显示 0% 或 100% |
| Token 过期 / 401 | “登录凭证已失效”，提供“更新 Token”；旧余额不作为有效当前额度 |
| 403 | “当前账号无法访问此额度”，提供重试与设置，保留其他独立有效分区 |
| 429 | “请求较频繁，稍后自动重试”，显示剩余等待时间 |
| 字段缺失 / 解析异常 | 对应分区 `—` 与“额度暂不可用”，其他有效分区继续展示 |
| 低额度 | 在主数字附近显示简短状态，不增加彩色大横幅 |
| 未知套餐 / 时间缺失 | 分别显示“套餐信息暂不可用” / “重置时间暂不可用” |

状态消息扩展内容高度，不覆盖刷新和设置。正常 100%–200% 缩放下完整显示；极小工作区或辅助文字放大时允许内容区滚动，底部操作保持可达。

## 9. 技术方案与代码边界

### 9.1 推荐方案

采用 **C# + .NET 10 LTS + WPF**。WPF 用于自绘布局、样式、绑定和可访问控件；Win32 互操作负责通知区域、定位和不激活显示。WPF 是 Windows 桌面 UI 框架；.NET 10 为 LTS，官方支持延续至 2028 年 11 月。[R4][R5]

| 候选 | 本项目取舍 |
| --- | --- |
| WPF + Win32 | 推荐；可明确控制小窗口与托盘生命周期，单独维护 Windows 外壳 |
| Tauri + WebView | 可复用部分 Web 界面，但增加 WebView/Rust 两侧边界；本草案优先原生方案 |
| Electron | 本项目只有一个小额度面板，暂不选择随应用分发浏览器运行时的方案 |
| WinUI 3 | 可作为后续评估项；当前视觉不依赖系统材质，首期不引入额外桌面框架迁移 |

此选择是实现偏好，不预先保证内存、性能或包体大小。React/TypeScript 规范继续适用于现有 Web/Android；Windows 原生端采用本节 C# 约定。

### 9.2 已落地工程目录（2026-11-04）

Core 不依赖 WPF、窗口句柄和真实系统时间。时钟、调度器、传输、凭据仓库可替换。UI 不直接发请求；原生句柄与非托管资源有明确释放路径。

C# 开启 nullable、隐式 using、编译警告作为错误；使用 PascalCase 公共类型/成员、camelCase 局部变量，异步方法以 Async 结尾。用不可变模型表达快照，避免 `dynamic`、空 catch、线程池直接更新 UI。

实现契约：套餐与用量分别保留值、更新时间与失败分类；`FetchResult` 汇总两个独立分区：

```csharp
public interface IUsageClient
{
    Task<FetchResult> FetchAsync(
        string accessToken,
        CancellationToken cancellationToken);
}
```

### 9.3 凭据与系统生命周期

- 使用 Windows Credential Manager 的 Generic Credential，通过 `CredWriteW` / `CredReadW` / `CredDeleteW` 管理；目标名称为 `KimiPocket/AccessToken`，不得在普通配置文件保存 Token。[R8]
- 凭据写入失败必须反馈错误，不得回退明文；超出存储能力的输入明确拒绝。释放读取凭据使用的非托管内存。
- JWT 本地解析只用于格式与到期预检，不把未验证的 Payload 当作服务端授权结果。
- Token、认证请求头、原始响应与个人标识不写入日志；异常消息脱敏。
- 普通设置如需持久化，使用 `%LOCALAPPDATA%\KimiPocket\settings.json`。当前首版仅有开机启动偏好，直接读取当前用户启动项，不生成额外配置文件；处理路径含空格与便携目录移动后路径失效。
- 当前用户单实例：二次启动复用已有进程并响应明确启动意图，不能产生重复图标。
- 显式退出时删除托盘图标、停止计时和网络请求、释放句柄。Explorer 重启收到 `TaskbarCreated` 后只恢复一个图标，不自动弹出面板。

## 10. 构建与分发契约

以下入口已在 2026-11-04 实现；构建脚本已通过格式检查、Release 编译、75 项测试和自包含发布，详见 [验证记录](../tasks/phase-6-windows-tray/evidence/README.md)。开发需要 .NET 10 SDK，`windows/global.json` 固定 10.0.403 并允许最新补丁。非系统 SDK 可由构建脚本 `-DotnetPath` 指定；手动命令需将对应 SDK 加入 PATH。

```powershell
# 在仓库根目录执行
# 还原依赖
dotnet restore .\windows\KimiPocket.sln --configfile .\windows\NuGet.Config
# 开发启动
dotnet run --project .\windows\src\KimiPocket.App\KimiPocket.App.csproj
# 编译与分析
dotnet build .\windows\KimiPocket.sln --configuration Release --no-restore -warnaserror
# 核心与适配测试
dotnet test .\windows\KimiPocket.sln --configuration Release --no-build --logger "console;verbosity=normal"
# 格式检查
dotnet format .\windows\KimiPocket.sln --verify-no-changes --no-restore
# 自包含发布（保持目录式发布，便于验证原生依赖）
dotnet publish .\windows\src\KimiPocket.App\KimiPocket.App.csproj --configuration Release --runtime win-x64 --self-contained true -p:PublishTrimmed=false --output .\dist-windows\win-x64
# 打包脚本：执行校验、发布并生成 ZIP
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-windows.ps1
```

首期分发 `Kimi-Pocket-windows-x64-<version>.zip`，解压运行 `KimiPocket.exe`，无控制台窗口，无需预装 .NET Runtime。自包含发布会包含运行时，不能把“小常驻进程”和“小分发包”视为同一个指标。[R9]

不强求单 EXE，不启用未经验证的 WPF trimming / NativeAOT；签名和自动更新在后续发布规范中单独定义。已新增 `windows/**/bin/`、`windows/**/obj/`、`dist-windows/` 的忽略规则；生成物和凭据不入库。自包含 ZIP 已完成本机解压验证，干净系统要求仍待 W12 实测。

## 11. 性能目标与验证方法

以下是首期工程目标，需要 Release 实机测量；不能引用 macOS 资源数据作为 Windows 的承诺。

| 指标 | 目标及测量方式 |
| --- | --- |
| 隐藏待机 CPU | 60 秒采样平均低于 0.5%，记录机器、系统、核心数和采样口径 |
| 常驻资源 | 启动稳定 5 分钟后 Private Bytes 目标 ≤100 MiB；同时报告 Working Set |
| 首次可用 | 本地 SSD 上进程启动至托盘图标可操作目标 ≤2 秒，不等待网络 |
| 悬浮响应 | 180 ms 防抖到期至已有内容首次绘制目标 ≤100 ms，网络不计入展示路径 |
| 生命周期 | 连续开合 100 次后无持续增长的计时器、句柄或图标；比较前后稳定值 |
| 待机活动 | 隐藏时无指针轮询、倒计时 UI 更新和持续动画；只保留合规的数据刷新 |

若超标，必须记录测量结果与瓶颈，再决定优化或调整指标，不以强制 GC 或隐藏测量数据通过验收。

## 12. 测试与验收标准

### 12.1 自动化验证

使用 xUnit 测试纯逻辑；网络通过替身响应，时间通过可控时钟，测试无需真实 Token。必须覆盖：

- **状态机**：179 / 180 ms 开启边界，299 / 300 ms 关闭边界；跨区取消关闭；主动隐藏后的再次武装；过期计时回调；菜单/设置与键盘入口。
- **图形数学**：4 / 7 段数量、0/1/边界比例、部分填充、间距与窄宽；主条连续；三项均为剩余语义，极小比例不误报耗尽。
- **数据解析**：脱敏 fixture、缺字段/空值/0/非数字/超界、300 分钟与 5 小时精确匹配、未知窗口、单接口失败、过期 JWT、倒计时归零不恢复额度。
- **刷新调度**：30/60 秒周期、15 秒缓存阈值、请求合并、超时、退避、429 等待、401 停止、403 分类、睡眠恢复、凭据代次隔离。
- **几何定位**：负坐标显示器、100/125/150/200% DPI、不同工作区、贴边钳制、图标不可见时的安全回退。
- **凭据适配**：保存/读取/替换/删除、存储失败不回退明文；真实系统集成测试使用独立测试目标并在结束时清理。
