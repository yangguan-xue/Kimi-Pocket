# SPEC-06: macOS 菜单栏常驻应用与悬停 HUD 规范 (macOS Menu Bar App Spec)

- **文档编号**：`SPEC-06`
- **对应阶段**：`Phase 5: macOS 桌面原生端体验与常驻扩展`
- **状态**：`PROPOSED` (待评审)

---

## 1. 目标与设计哲学

### 1.1 核心目标
为 macOS 用户打造一款常驻系统顶栏（Status Bar / Menu Bar）的轻量级用量仪表盘。用户无需打开完整网页或应用窗口，仅需将鼠标悬停在顶栏图标上，即可在一瞬间无感获取 Kimi Code 剩余额度与重置倒计时。

### 1.2 设计哲学
- **极简无感**：常驻系统顶栏，内存占用极低（< 25MB），0% 闲置 CPU。
- **即指即现 (Zero-Click HUD)**：鼠标悬停自动浮现，鼠标移开平滑隐退；保留点击交互以支持钉住 (Pin) 与高级配置。
- **原生质感**：沉浸式暗色毛玻璃（macOS Native Material），严格遵循 Apple Human Interface Guidelines (HIG) 与 Obsidian Dark 调色体系。

---

## 2. 技术选型评估与决策

| 方案 | 悬停 (Hover) 支持能力 | 资源开销 (常驻内存) | 跨域与网络能力 | 实施结论 |
|---|---|---|---|---|
| **Electron** | ❌ **不支持**（macOS 系统下 `tray.on('mouse-enter')` 被底层限制无法触发） | ❌ 极高 (200MB ~ 350MB) | 原生 Node 支持 | **直接否决** |
| **Tauri 2 (Rust + WebView)** | ⚠️ 较弱（标准 TrayIcon 仅支持点击，需写 Cocoa 原生 Hook；浮窗首次唤起有毫秒级白屏或渲染延迟） | 🟡 中等 (40MB ~ 80MB) | Rust 后端请求直连 | **备选** |
| **Swift 原生 (SwiftUI + AppKit)** | ✅ **完美支持**（通过 `NSStatusItem.button` 安装 `NSTrackingArea` 捕获 `mouseEntered/Exited`） | ✅ **极低 (15MB ~ 25MB)** | `URLSession` 直连（无 CORS 限制） | **最佳首选方案** |

### 决策结论
采用 **Swift 6 + SwiftUI + AppKit** 单可执行程序方案。
- 工程结构采用 **Swift Package Manager (SPM)** 构建，无庞大 Xcode 强绑定，直接支持命令行构建与自动化打包。
- 网络请求使用原生 `URLSession`，天然绕过浏览器同源策略（CORS），直连 Kimi 官方接口。
- Token 存储对接系统 **macOS Keychain (钥匙串)**，确保凭证物理级安全。

## 3. 顶栏图标 (Status Item) 交互与状态机规范

### 3.1 图标规格与渲染
- **尺寸规格**：`18x18 pt`（Retina 屏 `@2x` 为 `36x36 px`）。
- **渲染模式**：`NSImage.isTemplate = true`，自动适配 macOS 浅色/深色菜单栏及壁纸自适应半透明反色。
- **动态状态徽标 (Badge)**：
  - **正常态**：单色 Kimi 核心 Logo；
  - **额度紧张态 (5小时剩余 < 20%)**：图标右下角点缀冰蓝（`#00E5FF`）微光圆点；
  - **额度告急态 (5小时剩余 < 5%)**：图标呈现琥珀橙色（`#F59E0B`）；
  - **Token 失效 / 离线**：图标降级为 40% 不透明度并附带微型叹号。

```
       [ 正常 ]         [ 额度紧张 < 20% ]     [ 额度告急 < 5% ]
     ┌──────────┐        ┌──────────┐        ┌──────────┐
     │    ▲     │        │    ▲     │        │    ▲     │
     │   / \    │        │   / \    │        │   / \    │
     │  /   \   │        │  /   \  ●│        │  /   \  ●│ (琥珀)
     └──────────┘        └──────────┘        └──────────┘
```

### 3.2 悬停触发状态机 (Hover State Machine)

为解决“快速划过菜单栏误触”与“移向浮窗时瞬间断开”的经典交互难题，必须严格实现延时防抖状态机：

```
                    鼠标进入图标 (mouseEntered)
       [ 待机 Idle ] ─────────────────────────► [ 悬停预备 (Pending 180ms) ]
            ▲                                               │
            │ 鼠标在 180ms 内移出                           │ 停留达 180ms
            │                                               ▼
            │ 离开浮窗/图标超过 250ms               [ 浮窗展开 (Active HUD) ]
            └───────────────────────────────────────────────┤
                                                            │ 点击图标
                                                            ▼
                                                   [ 浮窗固定 (Pinned Mode) ]
```

#### 关键时钟参数与规则
1. **激活防抖阈值 (`Hover Dwell Threshold`)：`180ms`**
   - 当用户从屏幕左侧快速滑动鼠标去点击右侧控制中心时，鼠标在图标上经过的时间通常小于 `100ms`，此时**不触发浮窗**。
   - 鼠标停留超过 `180ms` 时，判定为有意查看，立刻执行渐入展开。
2. **退出容错逃逸期 (`Exit Grace Period`)：`250ms`**
   - 鼠标从菜单栏图标移向下方浮窗的过程会短暂经过无界面的屏幕空隙。
   - 在鼠标离开图标的 `250ms` 缓冲区内，浮窗保持可见；
   - 一旦检测到光标进入浮窗区域，计时器重置，浮窗持续稳定展示；
   - 只有当光标同时离开图标与浮窗超过 `250ms` 时，浮窗以 `150ms` 线性淡出隐藏。
3. **左键点击 (Left Click) — 模式切换**：
   - 悬停模式下为临时预览（Peek）；
   - 用户单击左键时，浮窗切换为“钉住模式 (Pinned)”，移开鼠标不再自动关闭，方便用户对照看板写代码；
   - 再次点击或点击窗口外任意区域解除钉住并收回。
4. **右键点击 (Right Click) — 系统菜单**：
   - 弹出标准原生上下文菜单（`NSMenu`）：
     - `立即刷新` (`⌘R`)
     - `复制剩余额度摘要`
     - `开机自动启动`（勾选项）
     - `设置 Access Token...`
     - `退出 Kimi Pocket` (`⌘Q`)

## 4. 悬停 HUD 浮窗视觉与内容架构

### 4.1 窗口规格与材质
- **窗口载体**：`NSPanel`（`.nonactivatingPanel` 风格，浮于其他窗口上方且不抢占前台键盘焦点）。
- **尺寸约束**：固定宽度 `280pt`，自适应高度约 `330pt`。
- **材质背景**：`NSVisualEffectView`（系统级暗黑超薄材质 `.ultraThinMaterial` / `.hudWindow`，搭配 `12pt` 圆角与 `1px rgba(255, 255, 255, 0.08)` 边框）。
- **定位对齐**：浮窗尖角自动对齐菜单栏图标中心 X 轴下方 `4pt` 处，若靠近屏幕最右侧则自动限制在屏幕边界内（`NSScreen.visibleFrame` 约束）。

### 4.2 浮窗内容分区

```
┌──────────────────────────────────────────────┐
│  Kimi Pro                      剩 28 天  [↻] │  <-- 顶部套餐与快捷操作
├──────────────────────────────────────────────┤
│  5小时额度                                   │
│  68%                                         │
│  [======================---------]           │
│  ● 01:24:30 后开始恢复                       │
├──────────────────────────────────────────────┤
│  本周用量                                    │
│  42%                                         │
│  [■■■] [■■■] [■■■] [   ] [   ] [   ] [   ]   │  <-- 7 段药丸条组件 (UI 不显露“7段”文本)
│  3 天后重置                                  │
├──────────────────────────────────────────────┤
│  总用量                                      │
│  65%                                         │
│  [■■■■■■] [■■■■■■] [■■■   ] [      ]         │  <-- 4 段药丸条组件 (UI 不显露“4段”文本)
│  当前周期有效                                │
├──────────────────────────────────────────────┤
│  更新于 14:32:05                   [固定 📌] │  <-- 底部状态栏
└──────────────────────────────────────────────┘
```

#### 各分区数据展示逻辑与文案纯净原则
> [!IMPORTANT]
> **文案去工程化与极致精炼原则**：
> 1. **纯净百分比**：百分比数值后严禁显示“余多少/总额”或“已用多少/总额”，仅保留大字百分比。
> 2. **三级色彩预警体系**：
>    - 用量 `< 80%`：正常冰蓝（`#00E5FF`）与冷翠绿（`#10B981`）；
>    - 用量 `>= 80% 且 < 90%`：**黄色预警**（`#F59E0B`），进度条、点亮药丸与主字颜色联动变黄；
>    - 用量 `>= 90%`：**红色告急**（`#EF4444`），进度条、点亮药丸与主字颜色联动变红。
> 3. **图形传达分段**：严禁在 UI 界面上向用户展示如“7段节奏”、“4段生命周期”、“(连续平滑)”等研发与实现维度的工程描述文字。分段与平滑完全由视觉组件本身的形态表达。

1. **顶部套餐行**：
   - 订阅状态：显示会员类别（如 `Kimi Pro`、`Kimi 商业版`）；
   - 到期天数：`剩 X 天`，当 `X <= 3` 时呈现琥珀色警告；
   - 快捷刷新按钮：微型旋转图标，点击触发即时静默刷新。
2. **核心模块一：5小时额度（时效最高，置顶）**：
   - 标题：纯净文案 `5小时额度`；
   - 形式：平滑单条水平进度条（`Capsule`，高度 `6pt`）；
   - 颜色：冰蓝（`#00E5FF`）渐变，额度告急时平滑过渡至珊瑚红；
   - 状态标注：`● 01:24:30 后开始恢复`。
3. **核心模块二：周用量**：
   - 标题：纯净文案 `本周用量`；
   - 形式：**7 个离散药丸段**（映射一周 7 天）；
   - 状态标注：`X 天后重置`。
4. **核心模块三：总用量**：
   - 标题：纯净文案 `总用量`；
   - 形式：**4 个离散药丸段**（每个段 `25%`）；
   - 状态标注：`当前周期有效` 或 `有效期至 YYYY-MM-DD`。
5. **底部操作栏**：
   - 显示最后数据同步时间戳；
   - 钉住 (Pin) 状态切换图标与快捷设置入口。

## 5. 数据核心与安全策略

### 5.1 数据拉取与缓存机制
1. **生命周期轮询**：
   - 浮窗关闭状态下：静默轮询周期为 `60s`；
   - 悬停浮窗展开瞬间：若当前缓存时间已超过 `15s`，立即在后台异步发起静默刷新，界面先行展示旧缓存并显示更新微动效，实现零等待；
   - 系统休眠监听：监听 `NSWorkspace.willSleepNotification` 暂停定时器，唤醒 `didWakeNotification` 时立刻重连拉取。
2. **网络接口与请求头契约**：
   - 完全遵循 `SPEC-02` 接口契约：
     - `POST https://www.kimi.com/apiv2/kimi.gateway.membership.v2.MembershipService/GetSubscription`
     - `POST https://www.kimi.com/apiv2/kimi.gateway.billing.v1.BillingService/GetUsages`
   - 通过 Swift 原生 `URLSessionConfiguration.ephemeral` 构建请求，注入标准 Header。

### 5.2 安全存储与凭据配置
1. **凭证隔离**：
   - 使用 macOS **Keychain (钥匙串)** 服务（服务名：`com.kimi.pocket.token`）进行硬件级加密存取，杜绝本地明文配置文件泄露风险。
2. **配置引导弹窗**：
   - 首次启动若 Keychain 未找到 Token，点击菜单栏图标直接唤出小巧的配置面板，包含：
     - Token 输入框（支持安全掩码）
     - 格式合法性与 `exp` 到期时间即时预检
     - 获取 Token 的图文指引提示

## 6. 系统集成与交付规范

### 6.1 系统能力适配
- **最低系统要求**：macOS 13.0 (Ventura) 及以上（全面支持 macOS 14 Sonoma 与 macOS 15 Sequoia）。
- **开机自启动**：采用现代 `SMAppService.mainApp.register()` 原生 API，无需旧式 LaunchAgent 守护进程或辅助助手 App。
- **Dock 栏图标隐藏**：`Info.plist` 中配置 `LSUIElement = true`，确保 App 仅存在于菜单栏，不在 Dock 栏和应用切换器 (`⌘Tab`) 中占用位置。

### 6.2 目录工程布局规范
在工程根目录下建立 `macos/` 原生工程：
```
macos/
├── Package.swift                     # SPM 依赖与构建配置
├── Sources/
│   ├── KimiPocketApp.swift           # 主程序入口 (NSApplicationDelegateAdaptor)
│   ├── Core/
│   │   ├── KimiClient.swift          # API 客户端 (URLSession + Connect 协议)
│   │   ├── KeychainManager.swift     # 钥匙串加密存取
```

## 7. 验证与验收标准 (Acceptance Criteria)

1. **悬停敏锐度与防抖验证**：
   - 鼠标快速滑过菜单栏时（停顿 < 150ms），浮窗**绝对不闪现**；
   - 鼠标停留 >= 180ms，浮窗以平滑动画展开；
   - 鼠标从菜单栏移入浮窗过程中，浮窗不出现任何闪烁或提前闭合。
2. **轻量与资源占用**：
   - 在 Activity Monitor 中，闲置常驻内存稳定在 **15MB ~ 25MB**，CPU 使用率在轮询间隙严格保持 **0.0%**。
3. **数据一致性验证**：
   - 浮窗内 5小时、周用量、总用量数据与 Web 控制台及 `SPEC-02` 解析规范 100% 严密对齐。
4. **编译与打包**：
   - 提供独立构建脚本，支持单命令编译出免签名的 `.app` 应用程序包并支持直接拖入 `/Applications` 运行。
